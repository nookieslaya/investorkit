# Import i raporty — plan integracji

## XTB: blokada mapowania
Nie dostarczono eksportu. Nie twierdzimy, że wspieramy format XTB. UI umożliwi wybór pliku i mapowanie, ale adapter xtb-verified pozostaje disabled z kodem SAMPLE_REQUIRED. Potrzebna zanonimizowana próbka z nagłówkami, datami, strefą, BUY/SELL, prowizją, różnymi walutami i ułamkami; zachować powtarzalne ID operacji. Sprawdzić, czy faktyczny eksport jest CSV czy XLSX — nie zmieniać rozszerzenia i nie zgadywać.
Kontrakt parsera: detect(bytes,metadata) → supported/unsupported/needsMapping; preview → normalized rows + issues + provenance; commit wyłącznie zatwierdzonego snapshotu. Limity wierszy/kolumn/pola, separator/encoding/daty jawne; parser CSV zgodny z quoting i newline w komórce. Nie wykonywać formuł; przy eksporcie neutralizować =,+,-,@. Plik traktowany jako dane.
Deduplikacja: preferowane ID brokera + namespace konta + typ. Fallback hash kanonicznych pól ekonomicznych + multiplicity/occurrence; dwie identyczne legalne transakcje muszą się zachować. Nakładające się eksporty bez stabilnego ID oznaczają niepewność i wymagają decyzji w podglądzie. SHA całego pliku wykrywa tylko identyczny plik, nie zastępuje deduplikacji wierszy. Unique receipt + transakcja przy commit i test równoczesnych importów. Eksport obejmujący niespójny ledger nie jest częściowo zapisywany bez jawnej decyzji użytkownika.

## PDF / URL
API zapisuje metadane i job, nie analizuje synchronicznie. Pliki poza publicznym katalogiem; losowe storage_key, magic bytes i faktyczne parsowanie PDF (nie tylko MIME/nazwa), streaming limit, limit100stron, timeout30s ekstrakcji, limit tekstu300k znaków. Parser w odizolowanym procesie z limitami CPU/pamięci, bez wykonywania JavaScript/załączników PDF. Skan bez tekstu → OCR_REQUIRED, OCR poza MVP. Dokument zaszyfrowany/uszkodzony → jawny błąd. AV scan przed zewnętrznym pilotem i dostawcą AI.
URL: tylko HTTPS443, allowlista źródeł w pilotażu, zakaz credentials, private/loopback/link-local/metadata IPv4 i IPv6; resolve i pin IP, ponowna walidacja każdego redirectu max3, limity stream/time, ochrona DNS rebinding i egress firewall. Jeśli bezpiecznego fetchera brak, endpoint disabled — nie prosty fetch dowolnego URL. Dostęp do pliku po autoryzacji/krótki signed URL.

## AI
Provider interface analyze(pages,profile,budget,signal). Konfigurowalny model z allowlisty serwera; OpenAI jako pierwszy adapter, bez kluczy po stronie klienta. Structured output + Zod. Fakty: {claim,value?,unit?,period?,citations:[{page,quote}]}; interpretacje: {text,basedOnFactIds,uncertainties}. Każdy cytat weryfikowany jako fragment znormalizowanego tekstu danej strony; brak zgodności usuwa twierdzenie i ustawia PARTIAL. Cytat nie dowodzi poprawności interpretacji — testować próbki ręcznie. Raport to niezaufane dane; instrukcje w PDF nie sterują narzędziami/promptem. Brak narzędzi web/action w wywołaniu analizy. Bez poleceń kup/sprzedaj, oddzielna sekcja ograniczeń.
Wejście maks.40k tokenów, wyjście4k, timeout90s, 1 aktywny job/użytkownik; limity konfigurowalne po pomiarach. Domyślny pilotaż: budżet0.50USD/użytkownik/miesiąc, hard cap0.15USD/analiza, kill switch systemowy i limit dzienny. To ustawienia aplikacji, nie ceny dostawcy. Przed wywołaniem oszacować górną cenę wg wersjonowanego cennika modelu (bez znanej ceny reject), atomowo zarezerwować budżet. Po wywołaniu usage×cennik, settle/release. Jeśli timeout po wysłaniu i brak usage: koszt UNKNOWN, zachować rezerwację do reconciliacji; bez automatycznego retry nieznanego naliczenia. Zapisywać osobno input/cached/output, walutę USD, pricing_version i koszt ekstrakcji jeśli płatna. Błędy/odmowa nie są raportem. Żadnego udawanego „0 USD”, gdy brak usage.
Cache: klucz (scope,sha256,extractorVersion,model,promptVersion). PRIVATE scope=userId; nie współdzielić przez hash. PUBLIC scope tylko po weryfikacji publiczności i warunków źródła, bez prywatnych tez/notatek w promptach; ogólna analiza może być wspólna. Cache lookup po kontroli dostępu; job dedupe/unique zapobiega podwójnemu naliczeniu. Personalizację później przechowywać oddzielnie.

## V2
Interfejs source connector: discover(since), fetch(document), policy(). Rejestr polityk: źródło, licencja/ToS URL, data weryfikacji, limity, identyfikacja klienta, zakres dozwolonego cache/redistribution. SEC EDGAR, ESPI/EBI i IR nie są jeszcze zweryfikowane; konektory domyślnie wyłączone. Etap V2 zaczyna się od sprawdzenia oficjalnych warunków, następnie scheduler, dedup, alerty. Nie implementujemy scrapingu ani nie deklarujemy praw do redystrybucji.

## I01/I03 — wdrożony ogólny podgląd CSV (19.11.2026)

Działa „Import CSV” w nawigacji głównej i zakładkach portfela, bezpośrednio `#imports`. To kompletna ścieżka plik → odczyt serwerowy → mapowanie → diagnostyka/podgląd, **bez zapisu transakcji**. Nie jest to adapter XTB ani gotowy import brokerski. I02/I04 nadal wymagają zanonimizowanej próbki; I05 (receipts/deduplikacja/commit) pozostaje niewdrożony.

- Kontrakty Zod w shared: CsvPreviewInput, CsvMapping, CsvPreview i CsvDetection. CsvParserAdapter ma detect(bytes,metadata), preview(input,instruments,asOf) i previewOnly:true. Ogólny parser zwraca needsMapping; unsupported odrzuca znane obce formaty lub limity, reserved supported pozwala później opisać rozpoznany format. Adapter `xtb-verified` nadal jest niedostępny z SAMPLE_REQUIRED, także w API.
- Endpoint `POST /api/v1/portfolios/:id/imports/csv-preview` przyjmuje JSON z bajtami zakodowanymi jako base64 i jawnymi ustawieniami. Nie zastępuje planowanego multipart `/imports/preview` ani `/imports/:id/commit`; tych operacji nadal nie ma. Brak batchId/previewRevision, ponieważ nic nie jest utrwalane. Odpowiedź zawsze canCommit:false / PREVIEW_ONLY.
- Limit oryginalnych bajtów5MiB,10000 niepustych rekordów danych,64 kolumny,16384 znaków pola,120 znaków unikalnego nagłówka. Pierwszy niepusty rekord jest nagłówkiem. Nagłówki puste/duplikaty blokują odczyt. Ograniczony body JSON8MiB uwzględnia narzut base64 i dotyczy wyłącznie tej ścieżki; pozostałe API nadal64KiB. Rate limit10/min tej operacji, sesja, Origin i owner scope. Kodowanie base64 sprawdzane także kanonicznie po dekodowaniu. Bez odczytu URL, plików dyskowych, zewnętrznych usług i nowych zależności.
- UTF-8 (fatal decode, BOM akceptowany) i jawny Windows-1250; separatory przecinek, średnik i tabulator. Nie zgadujemy kodowania/separatora. ZIP/XLSX, OLE/XLS, PDF, BOM UTF16 i NUL odrzucane. Parser obsługuje escaped double quotes oraz CRLF/LF/CR w cytowanych komórkach. Błędne cudzysłowy nie produkują pozornie pełnego wyniku. Różna liczba pól jest błędem wiersza; dodatkowe pola pozostają widoczne.
- Mapowanie indeksami kolumn, bez automatycznej zgadywanki nagłówków brokera. Jawny przycisk dopasowuje wyłącznie standardowe nazwy kind/occurredAt/currency/amount/symbol/mic/quantity/unitPrice/commission/commissionCurrency/fxToBase/fxAsOf/note/sourceId. Przed mapowaniem rodzaju/dat/waluty liczby poprawnych/błędnych wierszy są null („nie sprawdzono”). Pozostałe pola wymagane zależnie od typu operacji.
- Rodzaje BUY/SELL/DEPOSIT/WITHDRAWAL, waluty PLN/EUR/USD. Liczby pozostają decimal strings; kropka/przecinek wyłącznie zgodnie z ustawieniem, bez separatorów tysięcy, notacji wykładniczej, abs() i zaokrągleń. Ilość/cena/kwota dodatnie, prowizja jawna>=0. Precyzja instrumentu respektowana. Daty ISO8601 z godziną i offsetem, normalizowane UTC; daty bez strefy i przyszłe są błędami. FX obcy wymagany z datą niepóźniejszą od operacji; wyłącznie PLN używa tożsamości1 i daty operacji przy pustych/brakujących polach FX. Kwoty i FX zgodne z istniejącymi skalami10/12.
- Instrument jest rozpoznawany wyłącznie wśród własnych danych przez dokładny symbol+MIC+walutę. Nie mapujemy tickera do Marketstack ani nie tworzymy instrumentu w podglądzie. Inna waluta prowizji jest błędem. Walidacja formatu nie sprawdza jeszcze sald/oversell ani możliwości atomowego zapisu całej historii; UI mówi o tym wprost.
- Provenance: SHA256 oryginalnych bajtów, nazwa i rozmiar pliku, jawne ustawienia/mapowanie, wersja parsera i checkedAt. Każdy wiersz ma numer rekordu i początkową linię fizyczną, raw cells, opcjonalne sourceId, issues i operation albo null. SHA nie jest deduplikacją transakcji. Dwa identyczne legalne rekordy pozostają dwoma rekordami; nie rozstrzygamy nakładających się eksportów.
- UI stronicuje po50 wierszy; całość do10000 jest sprawdzana na serwerze. Wynik i plik wyłącznie w pamięci komponentu, bez React Query cache/localStorage. Zmiana pliku, mapowania, kodowania lub separatorów natychmiast usuwa wynik; AbortController i numer rewizji ignorują spóźnione odpowiedzi, także po wyjściu z widoku. Przycisk czyszczenia usuwa plik z pamięci. Surowe wartości renderowane jako tekst React, bez HTML/formuł i eksportu do arkusza. Do pobrania wyłącznie jawny, publiczny przykład ogólnego CSV z fikcyjnymi danymi.
- Repozytorium wykonuje REPEATABLE READ / READ ONLY i pobiera tylko własny portfel oraz instrumenty. Nie przechowuje pliku, operacji, cen, FX, receiptów ani snapshotów. Istniejący silnik finansowy nie został zmieniony. Następny etap importu wymaga próbki I02, weryfikacji I04 i dopiero potem atomowego commit/deduplikacji I05.
